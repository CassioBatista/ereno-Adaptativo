\section{Failure detection, trust level and the control interface}
\label{sec:api}

A runtime-switchable IDS is only operable if its switching rests on evidence and is
observable. ReSIDS takes the evidence from Disaster-FD~\cite{disasterfd2025}, a federated
failure detector with one monitor process colocated with each node. The architecture has
two roles, divided by competence: \emph{Disaster-FD} detects failures and publishes a
\emph{trust level}; the \emph{ReSIDS agent} on each node decides its own learning mode from
the trust level of its colocated monitor. Disaster-FD supplies evidence and never a mode.
This section specifies the interface between the two as a contract and separates what is
implemented from what is specified (Section~\ref{sec:api-status}).

\subsection{Trust level: Disaster-FD supplies the evidence, the agent decides}
\label{sec:api-authority}

Each monitor probes three targets every 5\,s: the aggregator and the node's two neighbours
on the ring overlay. Following the impact-factor model that Disaster-FD inherits from
Impact-FD, each target carries a weight---50 for the aggregator, 15 for each
neighbour---and the trust level (TL) is the sum of the weights of the targets currently
trusted, so $\mathrm{TL} \in \{0, 15, 30, 50, 65, 80\}$. The trust level is the quantity
Disaster-FD already computes; the interface adds only its mapping to a learning mode, in
the agent (Table~\ref{tab:authority}).

\begin{tabular}{@{}llp{0.52\linewidth}@{}}
\toprule
Trust level & Mode & Condition \\
\midrule
$\mathrm{TL} < 30$ & local & neither the aggregator nor both neighbours trusted: the node keeps the specialists it holds and exchanges no models \\
$30 \leq \mathrm{TL} < 50$ & GL & both neighbours trusted, the aggregator not \\
$\mathrm{TL} \geq 50$ & FL & the aggregator trusted \\
no TL for $F$ & local & the colocated monitor is silent \\
\bottomrule
\end{tabular}
\end{table}

Placing the decision in the agent follows from where the evidence is. A monitor colocated
with the node shares every partition with it: when the node is cut off, its own trust
level drops, and no remote decider on the far side of the partition is needed to move it
out of FL. Letting the detector report evidence rather than issue commands also bounds what
a faulty or compromised monitor can do: it can misreport a trust level, but it cannot
choose a mode outside the policy, reconfigure the agent, or act on any node other than its
own. The policy is deterministic and recorded with each decision, so every switch can be
re-derived from the trust level that caused it.

The modes are asymmetric, and the policy follows the measurements. Under GL, recall holds
from 14 nodes down to 3 because the retained booster union keeps every specialist; under
FL, the same loss removes specialists from the aggregate, and the aggregator is a single
point of failure. Returning to FL means re-accepting the hub, so it requires the
aggregator itself to be trusted---its weight alone reaches the FL band---and that evidence
to persist. The local mode, absent from earlier versions of the interface, expresses a node
that can reach neither the aggregator nor its neighbours and can only keep detecting with
the models it already holds.

\paragraph{Settle time.} Disaster-FD updates the trust level after each probe, target by
target, so at a change of conditions the trust level passes through intermediate values:
when the aggregator is lost a fraction of a second before a neighbour, the trust level
goes from 80 to 30 to 15, and an agent that switched on every observation would move from
FL to GL to local within one second. The agent therefore commits a band only after it has
held for $S$ seconds. Table~\ref{tab:settle} shows the effect on a 14-node run of
Disaster-FD (Section~\ref{sec:api-pilot}). One probe cycle, $S = 5$\,s, removes every
transient while delaying a switch by less than two cycles; it is the default.

\paragraph{Stale trust level.} If no observation arrives for $F = 15$\,s, three probe
cycles, the agent falls back to local learning. A silent monitor is not evidence that the
aggregator is healthy, so the fallback moves away from it. This rule replaces the watchdog
of earlier versions, which acted only when the local detector failed and only from FL to
GL; it now covers every mode and is decided by the same policy.

\paragraph{Time reference.} The agent infers no time from the traffic: the time reference
is Disaster-FD's probe cycle, and the window of an event is what the agent scored between
two cycles. Traffic timestamps, where the protocol carries them, travel only as optional
metadata for correlation with the monitored system's own logs, so the same contract applies
to timestamped protocols and to datasets with no time at all. Protection latency is
therefore the time Disaster-FD takes to distrust a target plus the settle time $S$.

Every switch records who took it and on what evidence: \texttt{decided\_by} is
\texttt{agent}, \texttt{reason} is \texttt{trust\_level} or \texttt{tl\_stale}, and the
event carries the trust level, the bands in force and the time of the observation used.
This makes the policy machine-checkable: a conformance script rejects any stream in which
the destination mode is not the band of the recorded trust level, a stale trust level leads
anywhere other than local, or a decision is attributed to anyone but the agent.

\subsection{Validation on a Disaster-FD run}
\label{sec:api-pilot}

The policy was replayed over the telemetry of a 14-node Disaster-FD run on a ring overlay,
83 minutes long, whose scenario defines five phases: all nodes isolated (0--15\,min), all
healthy (15--30\,min), an outage of the aggregator and of most neighbours (30--45\,min), a
partial recovery without the aggregator (45--60\,min) and a full recovery (60--83\,min).
The run directory records no start time; it is estimated from the end of the first phase,
the first jump to $\mathrm{TL} = 80$ minus 15 minutes, with a spread of 3.8\,s over the 14
monitors, and the delays of Table~\ref{tab:settle} are relative to that estimate.

All 41{,}802 observations conform to the trust-level schema. With $S = 5$\,s every node
makes exactly the four switches of the scenario---local to FL, FL to local, local to GL and
GL to FL---and spends 99.0 to 100\% of each phase in the expected mode, the remainder being
the switch delay after each boundary. The 14 nodes switch within 4.9\,s of one another at
every boundary, which bounds the interval in which part of the federation is still in the
previous mode. The largest gap between two observations of a monitor is 4.8\,s, so the
stale rule never fires. The 14 event streams conform to the event schema and to the policy.

\subsection{Observation surface}
\label{sec:api-events}

Three event types carry every state change (Table~\ref{tab:events}). One is an action, the
switch, and only it carries \texttt{decided\_by}; the other two are observations of
Disaster-FD that the agent may relay. An event refers to a closed window between two
probe cycles and carries its bounds, distinct from \texttt{ts}, the emission instant.

The interface is domain-neutral. What a domain fixes is bound by a \emph{profile}: the label
set the specialists are trained on, the source of attribution of an alarm---a protocol's
publisher identity, a device address, or none---and whether the traffic carries
timestamps. The profile in force is reported with the stream, so no field depends on an
implicit vocabulary.

\subsubsection{Behavioural contract}

What a consumer may rely on is not expressible in a schema, so it is stated separately:
events are ordered by \texttt{seq} ascending; \texttt{seq} starts at 1, has no gaps, and
continues across restarts; \texttt{since} is exclusive; retention is bounded and a
\texttt{since} below it yields \texttt{410 Gone} rather than a silently short answer.

The operative rule is that a consumer must reconcile using the highest \emph{contiguous}
\texttt{seq} it has received, never the highest \emph{seen}. The difference is not
cosmetic. Once a later notification arrives, the tail is current while an earlier event is
still missing, and the hole becomes invisible. Measured on the replay harness at 20\%
notification loss: \textbf{33 events permanently lost} with the tail test, \textbf{zero}
with the contiguous one. The same request subsumes liveness---an empty answer means alive,
no gap, and nothing to recover---so a separate periodic probe costs a round trip and buys
nothing.

\subsubsection{False positives and the window}
\label{sec:api-fp}

The alarm load sets how alarms must be aggregated. Replaying a benign-only stream, in which
every alarm is by construction a false positive, 252 of 724 one-second windows contain at
least one flagged sample (34.8\%). The two populations separate on volume rather than on
corroboration: a median of 56 flagged samples per window for false positives against 973
for true alarms. Triaging on volume, plus the flagged \emph{fraction}---which recovers
sparse attack windows of one or two samples, where no volume threshold can be met---keeps
97.9\% of attack windows at a window false-positive rate of 0.14\%, with thresholds
selected out of sample on earlier blocks of the trace and a 25\% safety margin over the
benign maximum; counting per specialist in addition raises it to 99.3\% at the same rate.

Because the window is the detector's cycle, its length is not fixed, and thresholds are
calibrated once. Calibrated at a 1-s cycle and then held fixed, the rule keeps 98.1--98.6\%
of attack windows with no false window when the cycle is \emph{stretched} to 2, 5 and
10\,s---the direction in which degradation pushes the detector. \emph{Shortening} it is not
safe: false positives cluster in time, so a short window that lands on a cluster carries a
high flagged fraction, and at 0.25\,s 6.7\% of benign windows alarm. Neither the volume nor
the fraction is invariant to the window length, and neither alone holds across cadences;
the rule is therefore calibrated at the shortest cadence the detector may use.

\subsection{Transport and security}
\label{sec:api-security}

The trust level travels between a monitor and the agent on the same host: an HTTP
\texttt{POST} on the loopback interface or a CoAP observation of the monitor's resource,
never routed. The event surface, read-only and bound to loopback, is observed by the
regional Disaster-FD through a resource directory and CoAP observation, with the
contiguous-sequence reconciliation above. Where a domain prescribes its own transport
security, the interface follows it: the REST binding runs over TLS directly, and the CoAP
binding moves to CoAP over TLS without changing the event model or the reconciliation
contract. Transport cost is not the deciding factor at this volume: DTLS 1.3 adds roughly
11 bytes per record, which still fits inside Ethernet minimum padding, so a protected
datagram occupies the same 84 bytes on the wire as an unprotected one.

Because no message from Disaster-FD is a command, the interface has no command surface to
protect. A faulty monitor can still misreport the trust level of its own node: reporting a
low level keeps that node in local or GL learning, a degraded but safe state; reporting a
high level while the aggregator is unreachable keeps that node in FL, where its training
stalls while detection continues with the models it holds. Either error is confined to the
node whose monitor made it. Byzantine monitors, which could vouch for an aggregator that is
itself compromised, are outside the scope of this version.

The policy is verifiable today on recorded telemetry: replayed over the Disaster-FD run, it
produces event streams that conform to the schema and to the policy, with exactly the
switches of the scenario. Intrusion notification and isolation require a decider that
can be trusted with the removal of a node, and are therefore left to a version that
models Byzantine monitors.
